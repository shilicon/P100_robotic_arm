# 公开范围与发布准备

## 可以纳入本次公开包

在发布者拥有后端代码权利的前提下：PC 服务、配置样例、独立提示词、协议测试样本、安装/校验/导出工具、通用鉴权函数和项目文档。源码选择 Apache-2.0，适用范围由根目录 NOTICE 限定。

## 不纳入公开包

厂商固件及定制代码、动作音效、动画、厂商提示词、未经授权的补丁上下文；模型和编译上下文；Windows/AMD/Python 安装环境；真实配置和密钥；带密钥的二进制；运行日志、音频、个人路径、缓存和历史实验目录。

厂商交付文件不等于取得了再分发授权。即使某些底层组件带有开源许可，也不能据此推定厂商新增代码和素材同样开放。取得厂商书面授权后，按明确范围、对应版本和上游通知另行评估。

## 操作

```sh
python scripts/test_offline.py
python scripts/export_public.py --check
python scripts/export_public.py --output dist/public-source.zip
```

导出器按允许目录、扩展名及根文件清单选择内容，拒绝符号链接、异常大文件、已知本地配置密钥和部分常见密钥格式。它不扫描原始备份，也不能替代完整授权核查或识别所有种类的秘密。

将 ZIP 解压到全新目录，核对 `SOURCE_SHA256.json`，检查 README、配置样例和文件清单后再初始化 Git。这样不会引入旧部署目录或其历史。不要强制添加被忽略的 `.private/`、配置或构建产物，也不要把压缩包连同私有工作区整体上传。

发布前仍需确认：后端代码确由发布者拥有或获授权；仓库名称和介绍不使用“完整厂商固件开源”“已验证 P100 NPU”或未测量性能表述。若旧密钥曾被公开，除了本地替换，还需要在所有实际部署端完成轮换；删除文件不能撤销已泄露的凭据。

导出脚本不会自动创建 GitHub 仓库、上传文件或改写远端历史。私有原始备份和本地固件工作副本不在公开包内。
